# Lane: Requirement and acceptance

Use when the task carries explicit acceptance criteria. Does the artifact meet
each current clause, including user corrections and exclusions?

For each clause, state satisfied, missing, or unverified with artifact evidence.
For a gap, quote the requirement, name the relevant file/line or observed result,
and state the minimum missing property. Make ambiguity and the reading used
explicit rather than silently inventing scope.

Review the assigned class of work: implementation, investigation, migration,
spike, or review. An honest upstream gap can satisfy an investigation; it does
not prove a requested implementation works. Do not add requirements, insist on
a preferred mechanism when only behavior was required, or block on paperwork.
Use `task-faithful-review` when that skill is available.
